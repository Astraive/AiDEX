# Scoped runtime MCP transport

`BridgeServer::bind()` owns a loopback Streamable HTTP MCP listener at an ephemeral `127.0.0.1` port. `lease(BridgeScope, Arc<dyn BridgeDispatcher>, CancelToken, ttl)` binds a backend-only `BridgeLease` to one active session and run. `BridgeLease::connection()` returns an opaque `BridgeConnection` for an adapter: `endpoint()` and `authorization_header()` are the only credential accessors. Debug redacts the credential, and the type has no serialization implementation. The native runtime request skips this field during serialization. Adapter configuration must remain ephemeral and must exclude the credential from saved snapshots and frontend values.

Each lease generates 32 random bytes. The admission registry stores only the SHA-256 credential digest. Expiry is bounded to one hour; dropping a lease, cancelling its token, ending a run or shutting down the server removes admission. The dispatcher rechecks active scope for discovery and immediately before effects. Lease and per-call deadlines also cancel admitted work.

The server implements `initialize`, `notifications/initialized`, `ping`, `tools/list` and `tools/call`; GET returns 405. Its JSON responses include MCP text content and `structuredContent`, with explicit `isError` tool failures. Tool names and schemas come from the dispatcher; no generic RPC or vault/configuration surface exists. Exact Host, loopback Origin and Bearer authentication checks apply. Initialization metadata is accepted, and an absent/null list cursor is supported; pagination is not advertised. Unknown fields and malformed argument envelopes are refused.

Four workers and a queue of 16 bound HTTP concurrency. Header size is 16 KiB, JSON bodies/results are 1 MiB, header/body reads have a shared absolute 10-second deadline and a maximum five-second individual read wait. Calls have a maximum 180-second deadline, further limited by lease expiry. Each lease admits 128 distinct tool request IDs; string IDs are limited to 128 bytes. Duplicate tool IDs with identical arguments return the cached outcome, while changed or in-progress requests fail without replaying an effect. Result caching is capped at 2 MiB, after which durable-history references replace cached bodies. One SDK MCP client owns a run lease; ID reuse by a separate client is refused rather than replayed.

`aidex-harness` provides the production dispatcher. It exposes only registered skill, web and MCP extension functions, filters full-access capabilities, seals plans through the regular broker, and retains complete outputs in encrypted history. Vendor filesystem/shell tools remain the adapter runtime's responsibility. A pending human approval keeps the same SDK actor and lease alive; calls from a paused scope cannot start another effect. Restart invalidates all executable decisions.

Real TCP fixtures verify authentication, Origin/scope denial, tool allowlisting, SDK metadata/null cursors, bounded identity, lease expiry and duplicate-effect suppression. Harness fixtures add actual sealed-plan allow/deny/cancel/restart and selected-source approval behavior.
