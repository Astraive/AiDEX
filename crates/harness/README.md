# Native execution

`NativeEngine` composes the encrypted `SessionStore`, real `ProviderRegistry`, selected `WorkspaceRegistry`, typed tool registry and `aidex-policy` with sandbox-managed process trees. Chat/plan turns offer no tools. Agent turns offer confined read/list/search/write/patch, Git and shell functions, plus bounded `agent_spawn`/`agent_result` child execution.

`NativeEngine::with_tools(store, registry, workspaces, events, scratch, tools, prompt_context)` accepts a prepared `ToolRegistry` and `Arc<dyn PromptContext>` before constructing the shared engine. `new` retains the built-in catalog and empty extension context. The daemon composes web/MCP/skill tools through this boundary; the harness does not execute model-selected operations outside the registry. `PromptContext::for_run(&SessionDetail, &Run, &ConfinedRoot)` binds selected extension scope and returns bounded instruction/data messages before each native request or external runtime request. Capability `permissions:full_access` hides a tool outside explicit full access; preparation and desktop inspection also reject a name-based bypass.

Runs have explicit pending/running/waiting_approval/completed/failed/cancelled/interrupted states. Message command IDs are durable and bound to their inputs. Approvals bind to a sealed plan fingerprint and include the planned diff. Decisions are saved before effects and duplicate decisions do not repeat execution. Restart never replays a non-idempotent effect: it marks active runs interrupted, invalidates old executable approval plans, and requires explicit continuation.

Drive policies and workspace project rules are evaluated before invocation/planning. Policy changes invalidate existing tool plans. Model invocation/child creation that needs a policy approval or rate-limit gate currently fails closed; tool approvals are implemented. Tool arguments and outputs, messages, instructions, checkpoints and memory remain encrypted in the session database. Durable events contain metadata; live text deltas are ephemeral and assistant text is coalesced into encrypted history.

Selected provider/model capabilities and output limits are checked. One explicitly configured `provider/model` fallback can run after a retryable inference failure; without a fallback, inference allows at most two retries with cancellable backoff. Long rate-limit cooldowns fail explicitly. Every retry/fallback consumes the durable run step budget. Cancelled, unauthorized, malformed or denied requests do not retry/fall back, and no tool effect is retried. Durable run metadata records inference retries and context trimming. The turn/operation step cap is 128 and the configured output cap is 32768 tokens; defaults are 16 steps and 4096 tokens. Children share their parent's scope, with four immediate children and depth two. Parent completion waits for active children, includes bounded terminal child results as untrusted context, and lets the parent produce its final response. Child completion never completes the root. External parents require safe resume support to incorporate child results.

Root `AGENTS.md`, `CLAUDE.md` and `.aidex/instructions.md` are read through confined tools within a combined 32 KiB source budget. Extension prompt context has a separate 32 KiB budget. Project text, file indexes, memory, child results and tool output are labeled as data. Replay budgeting removes oldest complete conversation/tool groups while retaining system instructions, the current user task and the latest tool pair; oversized tool strings are clipped only in the request view. Complete encrypted history is preserved. A request whose mandatory instructions/tool schemas cannot fit still fails explicitly. Effect-free argument/planning errors return structured tool results for model repair; policy/confinement denials and uncertain execution failures remain terminal.

Registered tools emit their real lifecycle, file and diff events through a metadata-only public sink. Complete `ToolOutput` envelopes (content, summary, applied diff, changes, warnings) stay in encrypted tool-result history. Managed processes emit start/exit events and bounded live output; incomplete lines and private-key blocks wait for their boundary or exit so split credentials are redacted before streaming. `agent.run_delta` identifies both root and child runs; root-only `agent.delta` remains available to existing clients. `agent.child_spawned` preserves parent/child run lineage. Parent cancellation or failure cancels active descendants.

Windows brokered processes have cleared environments, tracked Job Object trees and watchdog limits. Filesystem and network confinement are unsupported. Supervised shell requests restricted confinement and fails closed; explicit `full_access` opts into brokered same-user execution. Hard policy restrictions still apply. `auto` has no automatic reviewer and uses supervised approvals. Ship `aidex-sandbox-exec` beside `aidexd`.

File-tool writes/deletions record encrypted before-content and expected after-digests. Restore uses atomic typed writes or non-recursive deletion, including restoring a deleted file and removing a created file, and refuses conflicting user edits or active execution. Checkpointing arbitrary shell/external-runtime mutations is not implemented. Read/search/context walks are bounded; semantic/vector indexing is not implemented. Bounded wire projections and paged history expose large records without truncating their durable encrypted contents.

The desktop's typed conversation/run/approval/checkpoint contracts are in `packages/client/src/dto/sessions.ts`, with RPC bindings in `packages/client/src/rpc.ts`. Tests use deterministic FakeProvider turns through the real service, plus a real Windows sandbox-helper shell process. Resuming an interrupted root appends matching tool results to both the run transcript and conversation history; later turns therefore retain complete tool-call pairs without repeating effects.

External follow-up turns with a saved safe runtime reference use `RuntimeOperation::Resume`, retaining the selected model, permissions and protocol identity. A runtime that cannot resume fails with an explicit new-session/context-handoff requirement. Cancelled effects are never replayed; cancellation is followed by a fresh turn when the user continues. Focused repository fixtures prove real edits, failing/passing check output, Git diffs, extension dispatch, public event privacy and managed process cancellation.

`RuntimeEvent::SessionStarted` persists the adapter's safe native reference into the active encrypted run before the callback permits prompting or effects. Root runs also update their session reference; children retain independent references. Changed duplicate start identities within one launch are refused. Approval snapshots and their references commit together before returning `Pause`, and an omitted final reference cannot erase the latest saved identity. Native snapshot/evidence verification and safe restoration remain the adapter's responsibility.

External agent runtimes that report `supports_mcp_bridge()` receive a backend-only `RuntimeRequest.bridge` lease from `aidex-runtime-bridge`. `NativeEngine::extension_tools(&BridgeScope)` and `invoke_extension(scope, request_id, name, arguments, cancel)` expose only registered `skill_read`, `mcp_tools`, `mcp_call`, `mcp_stdio_call`, `web_search` and `web_fetch` functions. Scope, active generation, mode, capability permissions, policy, exact sealed plan and cancellation are checked before execution. Bridge calls consume the same durable step budget. Complete arguments/results stay encrypted; public tool events contain metadata. Generic RPC, configuration and secret reads are absent from this catalog.

External SDK launches evaluate `model.invoke` before prompt-source reads and before each actor starts. SDK model routing is conservatively classified as remote; verified local SDK routing is not currently represented by the adapter contract. Denied or approval/rate-limited model gates fail closed, and prompt preparation failures leave a terminal failed run rather than an orphan pending record.

When a bridge plan needs human approval, the HTTP call waits at most 120 seconds on a once-bound decision. The durable approval includes its bridge call identity and sealed fingerprint. `respond` signals the existing waiter and leaves the SDK actor running. Denial, timeout, restart and cancellation cannot execute or replay that plan. Only one pending approval per run is admitted; vendor approval requests cannot overlap a bridge approval. Completion closes effect admission and waits for already accepted calls. Global cancellation revokes leases and permits a fresh listener for later runs. `reconcile_after_unlock()` interrupts stopped active work and expires its pending approvals after private record access becomes available; it never resumes execution.

Explicit `SessionConfig.skill_ids` are loaded after extension scope binding with the real `skill_read` broker plan. Read-only policy-allowed content is injected as bounded, untrusted source text and takes priority over optional discovery metadata. A source that needs approval is deferred to an actual offered tool call. Hard denial prevents its read. SDKs without a bridge receive actual allowed selected content and no unavailable discovery-function hints. Chat/plan turns do not offer bridge tools. Projectless selected-source loading requires a workspace and does not run implicitly.
