# Native portable extensions

`aidex-extensions` provides real portable skill files, plugin packages, a shipped marketplace catalog and a native MCP client. The daemon composes this service with its drive paths, vault and live network gate. The harness binds each authenticated session scope and registers the service's `aidex_tools::Tool` adapters, so extension effects use the same sealed plans, policy facts, permits and approvals as built-in tools. See [API.md](API.md) for Rust/IPC contracts.

Skills live as `SKILL.md` files under the drive's skills directory. Plugin manifests and their declared skill files live under its plugins directory; a bounded metadata registry in private configuration stores trust, enable state and grants. Installation validates everything before the registry commit. Changed package content stops contributing to agent catalogs. Uninstall removes only declared regular files whose digests still match the installed package; additional or user-modified files remain on the drive.

The marketplace is a versioned local catalog compiled from the three first-party packages in `packages/`. Browsing has no effects. Installation requires the exact version and SHA-256 digest plus explicit trust and workspace/profile grants. Users can also import external manifest-and-skill packages. Executable third-party code is not loaded into the daemon.

Catalog reads never start a server, resolve a secret, authenticate or contact the network. Explicit MCP connect/discover initializes the server and retrieves its real paginated tool definitions. Native `mcp_tools` returns the cached actual schemas/revision and the correct `call_tool_name`; `mcp_call` performs HTTPS calls, and `mcp_stdio_call` calls owned stdio processes. The latter requires full access on Windows because filesystem/network confinement cannot be supplied there. Empty grant lists deny access; `*` is an explicit broad grant. Connected hidden server state belongs to the first native session that executes a call and cannot be used by another session until explicit reconnect.

Stdio uses the shipped sandbox helper and only its owned process-tree handles. Drive-contained command, argv and cwd paths normalize to `drive:relative/path` and resolve against the current drive root after relocation. Bare PATH commands and host-absolute executables remain host-dependent. HTTPS uses verified TLS, no ambient proxy/cookies or redirects, bounded JSON/SSE bodies and at most sixteen workers across active and closing connections. A cancelled HTTPS caller stops waiting immediately; its blocking HTTP worker closes within the configured timeout and no tool effect is retried automatically. Stdio cancellation sends the protocol notification and kills the owned tree.

Credential references resolve only for consumer `mcp:<server-id>` through atomic version checks and short-lived vault handles. Plans seal value-free vault record revisions; rotation requires explicit reconnect and rejects older approvals before transport. Credential bytes are zeroized, are never included in metadata or model context, reflected values in schemas/server metadata reject discovery, and echoed credential values in server output are redacted. Disabling/removing/disconnecting interrupts active calls; terminal `shutdown()` cancels pending discovery and stops owned processes. Every HTTP exchange checks the live network/vault gate before credentials and sending, while reading and while waiting. The daemon also disconnects pending and idle servers when entering offline mode or locking the vault.

Administrative connection jobs return immediately with `connecting` status and publish sanitized `last_error` on failure. Jobs outlive their initiating RPC response; explicit cancel/disconnect, vault lock and shutdown stop them. At most sixteen active/closing jobs are permitted, and stale generations cannot publish connections. Manual-only skills require explicit user selection and `user_invocable`; their IDs cannot be guessed to bypass this boundary.

This implementation supports MCP tools over newline stdio and Streamable HTTPS, negotiated protocol versions 2025-06-18 and 2025-03-26. It intentionally does not advertise OAuth, sampling, elicitation, resources, prompts, legacy HTTP+SSE or resumable streams. HTTPS disconnect forgets the session locally; HTTP DELETE termination is unsupported and server resources rely on remote expiry/cleanup. Input/output schemas support an explicitly bounded subset; unsupported constraints and references reject discovery. Server annotations never lower permissions. Restart does not automatically reconnect a server.

Verification: `cargo +1.99.0 build -p aidex-sandbox --bin aidex-sandbox-exec`, then `cargo +1.99.0 test -p aidex-extensions`. Tests cover durable lifecycle, passive discovery, schema/revision grants, live offline denial, session ownership, package integrity/preserved user files, drive-relative relocation, shutdown during discovery, bundled marketplace checks and a real Windows sandbox stdio MCP fixture.

Design references: T3 Code's scoped MCP service and adapter pattern (the local reference repository has MIT copyright notices) and the official MCP [transports](https://modelcontextprotocol.io/specification/2025-06-18/basic/transports), [lifecycle](https://modelcontextprotocol.io/specification/2025-06-18/basic/lifecycle), and [tools](https://modelcontextprotocol.io/specification/2025-06-18/server/tools) specifications. This crate is a Rust reimplementation and contains no copied T3 Code source.
