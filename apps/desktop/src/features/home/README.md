# Home feature

Owns the desktop landing screen and its view-specific content. Cross-feature navigation and shared shell remain in `src/app` and `src/layouts`.

The Home composer takes a prompt and attachments (picked, pasted, dropped on the composer, or a large paste folded into `pasted-text.txt`). Attachments are prepared and checked here like in a conversation (`../chat/attachments/`) but not uploaded: submit hands the prompt and the prepared attachments to the new Chat or Agent page in memory (`pendingPrompt`, `pendingAttachments`), which uploads them after it creates the conversation and sends.

`SystemOverview` shows live AiDEX Core status (state, uptime, pid, IPC version, with Start when stopped), drive health (volume, schema, free space, attachment, migration), and a host summary (OS, CPUs, strongest sandbox level). While AiDEX Core runs, `WorkspaceList` shows the drive's workspace registry (`workspace.list`, most recently opened first, selected and unavailable roots marked) and `LiveEvents` (`../system`) shows the last few events and then follows `events.subscribe`. The Home sidebar (`src/layouts/HomeSidebar.tsx`) is live as well: Projects lists the first seven registered workspaces (`workspace.list`; choosing one makes it the current project and opens its workspace page) with Add workspace, and Recent chats lists the seven newest conversations that are not locked (`conversation.list`), each opening as a chat or agent conversation by its mode.
