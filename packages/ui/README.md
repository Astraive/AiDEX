# Shared UI package

`@aidex/ui` holds the design tokens and accessible React components that AiDEX frontends are built from. App screens compose these components; they do not define their own styled markup. Add a component here, rather than in an app, whenever a screen needs a new visual building block.

## Entry points

| Import | Contents |
| --- | --- |
| `@aidex/ui/styles.css` | Design tokens, base element styles, the light theme, density blocks (`html[data-ui-density]`, legacy `html[data-density="compact"]`), the `data-chat-width` / `data-message-spacing` blocks, thin 6px scrollbars, and `html, body { overflow: hidden }`. Import once in the app root layout. |
| `@aidex/ui/themes` | `accentPresets`, `DEFAULT_ACCENT`, and `applyAccent(color)` for runtime accent changes; `applyAppearance(tokens, root?)`, `appearanceAttributes`, `appearanceVariables`, `codeLineHeight`, `DEFAULT_APPEARANCE_TOKENS`, the `*_RANGE` constants (chat text 12–20, code text 10–18, sidebar 208–480px), and the `AppearanceTokens` / `UiDensity` / `ChatWidth` / `MessageSpacing` types (plus the `AppearanceAttributes` / `AppearanceVariables` / `AppearanceRoot` result types) for the sizing and layout options. Interface scale is not here: the desktop host sets it as webview zoom. |
| `@aidex/ui/icons` | Project-owned 24×24 stroke icons, the AiDEX `LogoMark`, and `BrandIcon` provider logos. |
| `@aidex/ui/primitives` | Controls, form fields, display atoms, and layout. |
| `@aidex/ui/components` | Product components, data display, and content display. |
| `@aidex/ui/desktop` | Desktop frames: shell, navigation, page layouts. |
| `@aidex/ui/installer` | Installer wizard frame. |

The package ships TypeScript source and CSS Modules; consuming Next.js apps list it in `transpilePackages`. Styles reference the `--aidex-*` custom properties in `src/tokens/tokens.css` instead of literal values. The accent family (border, soft, ring, focus) derives from `--aidex-color-accent`, so `applyAccent` re-themes all of it. Sizes are px tokens at the comfortable density (`--aidex-control-*`, `--aidex-row-*`, `--aidex-icon-*`, spacing, radius, shell and page widths, the `--aidex-z-*` ladder); `src/tokens/README.md` lists them with the density tables and the breakpoint constants. Keep body leading unitless (`--aidex-leading-body`).

Dialogs (including the command palette and the image viewer), menus, tooltips, selects, toasts, scroll areas and collapsibles are built on [Base UI](https://base-ui.com) (`@base-ui/react`, pinned to 1.4.1 and imported by subpath, e.g. `@base-ui/react/menu`) and wrapped in CSS-module components with the APIs below; apps never import Base UI themselves. See [Overlays and layers](#overlays-and-layers).

## Catalog

Every component accepts its root element's props (including `ref` and `className`) unless noted. Sizes are px at the comfortable density. Compact takes 4px off control and row heights, and spacious adds 4px (`row-lg` is 40 / 44 / 52). The full table is in `src/tokens/README.md`.

## Overlays and layers

- **Stacking.** Tokens set the order: `--aidex-z-overlay` 40 (drop overlays), `--aidex-z-sidebar-overlay` 45 (the overlay sidebar; its scrim sits one below), `--aidex-z-dialog` 50 (dialogs and `CommandPalette`), `--aidex-z-dialog-media` 60 (the image viewer), `--aidex-z-toast` 100, `--aidex-z-popover` 130 (popovers, menus, selects, `CommandMenu`, `ModelPicker`), `--aidex-z-tooltip` 140. A menu, select, tooltip or toast opened over a dialog is always on top and usable.
- **Layer stack.** Open dismissable surfaces register in one stack (`pushLayer(element, { modal })` returns the removal; `popLayer`, `topLayer`, `isTopLayer`). Only the top layer answers Escape, and a press inside a layer opened on top of another, or inside an element marked `data-aidex-layer` (the toast region, menu and select portals, the dialog, image viewer and command palette popups, the open overlay sidebar), is not outside the one below (`isInsideDescendantLayer(target, element)`). `hasModalLayer()` tells window shortcuts to stand down while a dialog, the image viewer or the command palette is open (the desktop's `useKeyChord` swallows them), and `layerCount()` lets Mod+B also wait while a select, menu or popover is open. A non-modal `Popover` closes when a modal layer opens over it.
- **Portal roots.** The `Dialog` and `CommandPalette` popups carry `data-aidex-portal-root`, and a `Popover` opened inside one portals there, so it stays inside the focus trap. A portal root never has a transform, filter or containment at rest (they would offset fixed-position children); dialogs scale only while entering and leaving.
- **Motion.** Popups enter and leave over 150–200ms (`data-starting-style` / `data-ending-style`) and unmount after leaving; with reduced motion (the OS setting or `html[data-reduce-motion="true"]`) they appear and go at once.

## Desktop shell

`AppShell` holds the rail, an optional sidebar, and main. The frame (8px pad and gap, 52px rail) is the same at every density. The app picks the sidebar mode: with the `sidebarLayout` helpers, the sidebar can dock while the window is at least `dockMinViewport(width)` wide (980px at the default 256px), which leaves main at least 640px. `src/desktop/README.md` has the details.

- **Docked** (`sidebarMode="docked"`). The sidebar sits beside main and collapses with a width transition (`--aidex-duration-panel`). A closed sidebar stays mounted, hidden and inert. With `onSidebarResize` or `onSidebarResizeEnd`, the shell adds a resize separator (`role="separator"`, a 16px hit area on the gap). You can drag it, press the arrow keys (8px, or 32px with Shift) or Home/End, or double-click it to reset the width (`onSidebarResetWidth`). The width shows inline while it moves, and `onSidebarResizeEnd` runs once, on release.
- **Overlay** (`sidebarMode="overlay"`). The sidebar floats over main, past the rail, at `--aidex-z-sidebar-overlay` above a scrim. Main is inert while it is open and focus moves into it. A press on the scrim, or Escape while it is the top layer, calls `onSidebarOpenChange(false)`. It registers in the layer stack and has no transform at rest.
- **Focus.** When the sidebar closes with focus inside it, focus goes back to `sidebarToggleRef`.
- **Main.** The `<main>` region is the `aidex-main` inline-size container (`@container aidex-main (max-width: 640px)` narrows the page and dock padding). It is `position: relative` and keeps a stable gutter for the 6px scrollbar.
- **Rail.** In a short window `NavRail` scrolls, with 12px fades at a hidden edge (`useOverflowEdges`), and keeps the current destination in view.
- **Tooltips.** `AppShell` mounts one `TooltipProvider` (600ms). The rail has its own 150ms group, so moving along it opens the next label at once.

## Composer layout

`Composer` is a card with a 22px radius and 16 / 12 / 12 / 16 padding (10 / 10 / 8 / 14 with `size="compact"`). The prompt uses `--aidex-text-chat` at 1.625 and grows from three lines (one when compact) to `--aidex-composer-editor-max` (min(40vh, 208px)), then scrolls.

- **Toolbar.** Attach is an `IconButton` sm (28px) and send is md (32px), 6px apart. The start group (attach plus `toolbarStart`) takes the room that is left. Plain text in it ellipsizes, and when even its buttons do not fit it scrolls sideways (with edge fades) instead of pushing send out; controls inside it draw their focus ring inset. The end group (`toolbarEnd` plus send) never shrinks.
- **Narrow composers.** The form is a `composer` size container. At 520px or less, plain text in the start group and the `ModelPickerTrigger` name are visually hidden (still read out), and the trigger keeps its icon width, so a start group that is still too narrow scrolls.
- **Attach menu.** With `attachActions`, the attach button itself is the `ComposerAttachMenu` trigger. ArrowDown or ArrowUp opens the menu on its first or last item, Escape returns to the button, and Tab closes it and moves on. While `attachDisabledReason` is set the menu does not open; the button stays focusable (`aria-disabled`) and its tooltip gives the reason. "Upload from computer" also carries the reason as its `disabledReason`.

## Brand icons

`BrandIcon` draws provider and agent-runtime logos from `icons/brands/brandGlyphs.ts`: generated, monochrome 24×24 path data (49 brands) from `@lobehub/icons-static-svg`, MIT licensed; see `icons/brands/NOTICE.md`. Do not edit the data by hand. Brand names and logos identify the provider only.

- **Color.** `tone="brand"` (default) colors the glyph with its brand color through the `--aidex-brand-color` custom property; glyphs without a usable color, and `tone="mono"`, inherit `currentColor`. In the light theme the brand color is darkened (`color-mix(in oklab, <brand> 78%, black)`, through the `--aidex-brand-color-strength` token) to keep contrast on light surfaces.
- **Fallback.** A key without a glyph renders a rounded-square monogram of up to two initials from `title`, or from `brandTitle(brand)` when there is no title (`monogram("llama.cpp server")` is "LS"; a single word gives its first two letters).
- **Accessibility.** Without `title` the icon is decorative (`aria-hidden`); with one it is `role="img"` with that name. Next to a visible provider name, leave `title` off.

## Model picker

`ModelPicker` is data only: the app maps its providers and models to `ModelPickerProvider` (`id`, `name`, `brand`, `status` ready · warning · error · disabled · setup, `statusText`, `kind` model · runtime · local, `setupLabel`) and `ModelPickerModel` (`key`, `providerId`, `name`, `shortName`, `description`, `contextWindow`, `capabilities` tools · vision · json · reasoning, `badge` new · default · custom, `unavailable`, `disabledReason`, `legacy`), and persists selection and favorites itself.

- **Layout.** A popover (360px wide, up to 380px tall) with a 40px provider rail of 32px buttons (Favorites, then providers; agent runtimes after a divider) and a search field above a listbox. Each rail button shows a status dot; its tooltip and accessible name name any non-ready state ("Groq — Unavailable. 401 Unauthorized"). Options are 40px tall, with the name at 13px and the detail at 12px. The active option is tinted, and gets the accent ring only after keyboard use (arrow keys or typing a search). A row shows a tooltip beside it (side right) only when that adds something: the disabled reason, the description, the full name when the display name is shorter, or text the row cuts off. Rail buttons and favorite stars use the `Tooltip` primitive; no native `title` remains.
- **Views.** It opens on Favorites when any listed model is a favorite, otherwise on the selected model's provider (or the first ready one). Favorites are ordered by rail order. A provider view lists favorites, then current models, then a "Legacy models" row that expands the `legacy` ones. Typing searches every provider: tokens are matched against name, short name, provider name, and key (exact, prefix, word boundary, substring, then fuzzy for tokens of three or more characters), favorites are boosted, and ties sort by name. The rail hides while searching.
- **Footer.** A provider that is not ready (or has no models) shows its `statusText` or a fallback with an "Open provider setup" button when `onOpenProviderSetup` is set. `onManageProviders` adds a "Manage providers" bar.
- **Keyboard.** Focus starts in the search field. ArrowUp/ArrowDown move the active option (`aria-activedescendant`), Enter selects it (or toggles the legacy row), Escape closes and returns focus to the trigger. ArrowLeft on an empty query or Shift+Tab moves to the rail, where ArrowUp/ArrowDown/Home/End move, Enter or Space selects, and ArrowRight or typing returns to search. Tab from search reaches the active row's favorite button. While open, Mod+1…Mod+9 choose the first nine enabled rows (hints show when `jumpModifierLabel` is set) and Mod+Shift+ArrowUp/ArrowDown switch provider, skipping disabled ones. Rows with a `disabledReason` are skipped and show the reason as their tooltip (side right).
- **Search helpers.** `rankBySearch(items, query, toSearchable)` and `scoreModelSearch(model, query)` expose the same ranking, for example to filter a model list elsewhere; `formatContextWindow(tokens)` gives "200K" / "1M".

## Attachments

Files enter through the `Composer` and render with `AttachmentTray` (before sending) and `MessageAttachments` (in a sent message). The components only display and collect files: the app validates, uploads, and decides what a kind is (`image`, `pdf`, `text`; any other kind reads as "File").

- **Intake.** With `onFiles`, the attach button opens a hidden `<input type="file" multiple>` (filtered by `accept`, reset after every pick). `attachActions` (for example "From project…") turn the button into a menu (`ComposerAttachMenu`, on `Menu`: ArrowDown or ArrowUp on the button opens it on the first or last item, typeahead moves the highlight, Tab closes it and moves on, and an action's `disabledReason` shows as its tooltip) that starts with "Upload from computer" (`uploadLabel`); `onAttach(openFilePicker)` replaces all of that with the app's own action. Pasted files become files when the clipboard has no plain text (blank text counts as none only when there is no HTML either). With text, only an image copied on its own does, that is when the clipboard's HTML is just the image (a browser's "Copy image"); everything else pastes as text, including rich copies that also carry a bitmap, such as cells from Excel (even empty ones) or a OneNote page (`shouldClaimFilePaste(files, plainText, html)`, a single linear pass that treats unclosed markup as text). A plain-text paste of `largePasteBytes` (32 KiB) or more, in characters or UTF-8 bytes, goes to `onLargePaste` instead of the field, unless the user pressed Ctrl/Cmd+Shift+V. `source` tells the app whether files came from `picker`, `paste`, or `drop`.
- **Dropping.** Dragging files over a composer shows a dashed overlay with a paperclip and `dropLabel`. `FileDropZone` makes a larger region, such as a whole conversation page, the drop target, with the same overlay over its visible part; a `Composer` inside a zone leaves drops to the zone, so files are never added twice. Do not nest zones. A modal over the zone (`Dialog`, `ImageLightbox`) keeps file drags to itself, so a file dropped on it never lands in the composer behind it; `containFileDrag` does this for other modal surfaces, and a drop target nested inside the modal still accepts its drags. The highlight follows a `dragenter`/`dragleave` count and resets on a drop anywhere, `dragend`, or Escape. Dropped folders arrive as unreadable `File` entries for the app to refuse.
- **Window guard.** Call `useFileDropGuard()` once at the app root (or `installFileDropGuard(window)`). Drop targets accept a drag by cancelling `dragover`; the guard refuses every other file drag (`dropEffect = "none"`), refuses links dropped outside a text field, and cancels every file drop, so a file dropped anywhere else never navigates the window. In Tauri this matters once `dragDropEnabled` is off, because the webview then handles drops itself.
- **Blocking.** `attachDisabledReason` disables the attach button, file paste, and drops, and shows the reason as the attach tooltip and in the drop overlay. `submitBlockedReason` keeps send unavailable (it stays focusable with `aria-disabled`, so the reason can be read) and shows the reason as its tooltip and as a hint under the composer. `canSubmitEmpty` allows sending blank text, for example when only attachments are ready.
- **Tray.** Images are 64px tiles with a 10px radius (`--aidex-radius-md`). The 20px tile buttons (remove, retry) have a 24px hit area (WCAG 2.5.8), 44px on touch screens. A tile has a preview button (`Preview <name>`, opens an `ImageLightbox` over the tray's images), an X (`Remove <name>`), a `NN%` progress strip while uploading (a `progressbar`), and, for a failed upload, a danger border plus a retry button (`Retry upload for <name>`) whose tooltip and description give the reason. Other files are 32px rows with a kind icon, name, status (`Text · 48 KB`, `NN%`, "Upload failed", or `statusText`), retry, and X. Failures are announced in a polite live region. `formatAttachmentSize` gives "3.2 MB" from 1 MiB up and whole kilobytes below, never "0 KB".
- **Sent messages.** `MessageAttachments` goes in a `ChatMessage` bubble above the text: images in a two-column grid of 4:3 tiles at most 210px wide (a single image spans both columns), with a placeholder showing the name while loading or after a failure; files as rows with a 13px name, the kind, page count, size, an optional `note`, and a Download button (`status: "loading"` shows a spinner while downloading). Tiles without `src` (and not `loading` or `error`) call `onRequestImage(id)` as they scroll into view, or at once when they lose `src` while in view (one `IntersectionObserver` per component watches every tile, with a 200px margin), and the viewer asks for the image it shows when the grid has not; the call can repeat for an id, so cache by id. `onImageVisibilityChange(id, visible)` reports when an image comes on screen (its tile in view, or the viewer showing it) and when it leaves, and reports `false` for every image still on screen when the component unmounts, so an app can keep on-screen images out of cache eviction (otherwise an evicted image in view is asked for again, which can loop).
- **Viewer.** `ImageLightbox` is a full-window modal (Base UI Dialog) above other dialogs. The close button takes focus on open (without showing its tooltip); one Escape or a click outside the image closes it, and focus returns to the opener. Prev/Next and ArrowLeft/ArrowRight wrap around, and the caption reads `<name> (i/n)` politely. Zoom runs from fit to 8x: a click on the image, or the zoom button (`aria-pressed`), toggles between fit and 2x around the clicked point; the wheel zooms around the pointer; `+`, `-` and `0` zoom in, out, and back to fit. While zoomed, dragging or the arrow keys pan. A missing or failed image shows "Image unavailable." ("Loading image…" while `loading`).
- **Data URLs only.** Thumbnails and the viewer display `data:image/...` URLs and ignore anything else (`safeImageDataUrl`): the desktop release CSP allows `data:` images but not `blob:`, and a preview must never fetch. Images are not draggable, so a thumbnail cannot be dropped back in as a new file.
- **Theming and motion.** Everything uses the `--aidex-*` tokens in both themes; the overlay fade, progress fill, viewer fade, and spinners stop under reduced motion.

## Markdown

`Markdown` renders model output, skill bodies, plans, and markdown artifacts with a dependency-free parser (`parseMarkdown(source)` returns the block tree; `markdownInlineText(nodes)` flattens inline nodes to text). Both are pure, so they run during static export and in unit tests.

- **Syntax.** ATX and setext headings, paragraphs, `*emphasis*`, `**strong**`, `~~strikethrough~~`, code spans, fenced code (rendered with `CodeBlock`, language from the fence), ordered, unordered, nested, and task lists, blockquotes, GFM tables with alignment, horizontal rules, inline and reference links, `<autolinks>`, bare `https://` and `www.` links, images, hard breaks, backslash escapes, and common entities.
- **Streaming.** An unclosed fence runs to the end of the text and renders as code (`data-streaming="true"` on its `CodeBlock`), so a response that is still arriving never flashes as prose.
- **Safety.** Raw HTML is never interpreted: `<script>` or `<img onerror>` stays literal text. Links and images keep only absolute `http(s)` URLs (links also `mailto:`) without embedded credentials, checked by `safeExternalUrl` (exported with `urlHost`); `javascript:`, `data:`, `file:`, relative, and obfuscated schemes become inert text. Links have no `href`, so the webview can never navigate: activating one (click or Enter) calls `onOpenLink(url)`, and the URL is the tooltip. Without `onOpenLink`, links render as plain text. Images are never loaded; they show as an image chip that opens like a link, or an inert chip inside a link's text (a README badge such as `[![CI](badge.svg)](ci)`). Nesting depth and delimiter runs are bounded, so hostile input cannot exhaust the stack, and parsing stays linear on long whitespace runs, deep bracket nests, and unclosed link titles, so it cannot freeze the UI.
- **Headings and chips.** `headingLevelOffset` shifts heading tags under the surrounding outline while keeping their look. `renderText` maps plain text runs (never code or link text), for example `(text) => renderSkillTokens(text, toChip)` to show `$skill` chips.
- **Sizing.** Text takes the surrounding font size (`--aidex-text-chat` in a `ChatMessage`). Prose uses `--aidex-prose-line-height` (1.625) and `--aidex-prose-block-gap` (12px) between blocks; `html[data-message-spacing]` sets them (compact 1.5 / 8px, relaxed 1.75 / 16px). Headings are 20 / 18 / 16 / 14 / 14 / 14px at line height 1.3, with 20px above and 8px below. Lists indent 20px with 4px between items. Inline code is 0.857em (12px beside 14px text) with 2 / 6px padding and a 6px radius. Code blocks and terminals use `--aidex-text-code` / `--aidex-code-line-height` (13 / 20px by default; the Appearance code size of 10 to 18px gives round(size × 1.54)), 12 / 14px padding, a 10px radius, and 28px header rows. `CodeDiff` passes the same size and line height to the diff renderer.

## Command menu

`CommandMenu` is the composer's `$` skills menu and `/` command menu: a `Popover` above the composer, sized to it, holding a listbox of sections. It is fully controlled; the app detects the trigger, filters and ranks `sections` from `query`, and inserts the pick. `CommandPalette` drives the same rows and key model from its own search field, in a dialog (the desktop quick search is built on it).

- **Focus stays in the text field.** Pass the composer's `textareaRef` as `inputRef` and the composer `ref` as `anchorRef`, and give the composer `suggestions={{ listId, open, activeId }}` (or spread `commandMenuFieldProps(...)` onto another field) so the field carries `aria-controls` and `aria-activedescendant` (option ids come from `commandMenuOptionId(listId, itemId)`).
- **Keyboard.** While open, ArrowUp/ArrowDown in the field move the active row through every row, disabled ones included (wrapping), Enter or Tab selects it, and Escape closes. These keys never reach the field, so Enter does not send. On a disabled row Enter and Tab do nothing and the menu stays open: no send, no other row, no focus move. With no active row, Enter and Tab behave as usual; Shift+Enter, Shift+Tab, and presses with Alt, Ctrl, or Meta always reach the field. Opening, and every change of `query`, highlights the first row even when it is disabled, so list the best match first: Enter never runs a lower row in its place. After that the highlight stays on its row while the row is listed, and otherwise moves to the first row. `resolveCommandMenuActive` and `commandMenuKeyAction` expose the same logic. The active row is tinted; it gets the accent ring only after the keyboard moved the highlight (`data-modality="keyboard"` on the menu), and opening the menu or a new query returns it to keyboard modality. The list is not a Tab stop of its own (`tabIndex={-1}`).
- **Pointer.** Hovering highlights a row (disabled ones too). Real pointer movement switches the menu to `pointer` modality, so the row is only tinted, with no ring. Clicking selects it without taking focus from the field; clicking a disabled row does nothing. A press outside, or focus moving elsewhere in the page, calls `onClose`.
- **States.** A disabled row is dimmed, keeps the full highlight when active, and carries `aria-disabled`, so the field's `aria-activedescendant` announces it as unavailable. `loading` with no rows shows `loadingText` with a spinner; no rows shows `emptyText` (t3code copy: "No skills found. Try / to browse provider commands." for skills, "No matching command." otherwise). A polite live region announces the result count, with the unavailable rows counted separately ("3 results, 1 unavailable"). The first match of `query` in each title is bold and underlined.
- **Tooltips.** A row's tooltip sits beside it (side right, 8px) and opens on hover. An item `tooltip` always shows; without one, the row shows its title and description there only while one of them is cut off. The internal `useTextCut(rootId, classNames)` hook checks that after each render; `ModelPicker` rows use it too.
- **Palette.** In `CommandPalette`, focus starts in the 40px search field and stays there (`aria-activedescendant`). ArrowUp/ArrowDown move the highlight with the same model (`commandMenuKeyAction`, `resolveCommandMenuActive`), Enter runs it, and the list is not a Tab stop, so Tab and Shift+Tab stay in the field unless `notice` or `footer` hold controls. Escape or a press on the backdrop closes it and returns focus to where it was. The active row stays in view as the arrows move and wrap, and the first row of a section brings its heading along. Rows are 32px (`--aidex-row-md`). The footer shows ↑↓ / Enter / Esc hints at 12px, hidden with the other keyboard hints (`html[data-keyboard-hints="false"]`).
- **Mentions.** `splitSkillTokens(text)` and `findSkillMentions(text)` find `$name` tokens (letters, digits, `_`, `-`, at least one letter; amounts such as `$20`, `$20k`, `$1.5` are not mentions).

## Plans and artifacts

- **`PlanCard`.** The plan's first heading becomes the title (a "Summary" heading right after it is dropped) and the rest renders with `Markdown` under it. Plans over about 20 lines (long lines count once per 100 characters) show a 10-line preview that fades out, with a "Show full plan" / "Show less" toggle (`aria-expanded`). `splitPlanMarkdown`, `planLineCount`, and `planPreview` expose the same logic.
- **`ArtifactCard`.** `formatByteSize` gives "1.5 KB"; `createdAt` is shown with `formatDateTime` in the viewer's locale inside a `<time>` element. `artifactKindLabel(kind)` gives the badge text; any kind that is not one of the seven, including names such as `constructor`, reads as "File".

## Code diffs

`CodeDiff` is the one diff component; every diff in an app renders through it. It wraps [`@pierre/diffs`](https://diffs.com) (Shiki-based) and adds an accessible header: file name, `+N −M` counts with a spoken "N additions, M deletions" summary, a unified/split `SegmentedControl`, and an `actions` slot.

- **Client only, lazy.** The header and a placeholder sized to the diff are prerendered (safe under `output: "export"`). After hydration the highlighter chunk (`CodeDiffRenderer`) loads with `React.lazy`; Shiki themes and grammars are further split into on-demand chunks, so a screen without diffs never downloads them.
- **No WebAssembly, no network.** Shiki uses its JavaScript regex engine (`preferredHighlighter: "shiki-js"`), so the Tauri CSP needs no `wasm-unsafe-eval`. Themes and grammars are bundled; nothing is fetched at runtime.
- **Theming.** Syntax colors come from the bundled `pierre-dark` theme. Surface, text, line tints, and fonts map onto `--aidex-*` tokens through the `--aidex-color-diff-*` tokens in `tokens.css`, set as `--diffs-*` custom properties on the library's host element. Code text uses `--aidex-text-code` at `--aidex-code-line-height` (`--diffs-font-size`, `--diffs-line-height`), so it follows the Appearance code size.
- **Accessibility.** Lines carry classic `+`/`-` markers, so changes never rely on color alone. Long lines wrap instead of scrolling, and the library's mouse-only hunk-expand controls are turned off.
